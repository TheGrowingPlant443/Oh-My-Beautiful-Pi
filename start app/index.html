Container mode: OMBP and every OMP child run together. Only approved host resources are exposed. Network requests must pass the website gateway.

Private ~/.omp · copy once

The first isolated Start copies your entire host ~/.omp, including credentials, .env, Git history, ignored files and custom folders. macOS uses the Linux VM; Linux uses its private container home. Later starts keep container changes. Nothing is written back to the host.

The container can read copied credentials. External symlinks are preserved but may dangle; sockets, FIFOs and devices cannot be copied as live endpoints and are counted in the launch log. Git push still needs usable credentials and allowed network access.

      Programs & desktop

      i

      Install into container gives this launcher a private, read-only copy of the required core and selected pinned Nix packages. Choose tools to change optional packages for the next Start; nothing installs when you save. Packages are built in the isolated Linux runtime (on a Mac, inside the launcher's VM). Dependencies can include additional usable programs: this is not a per-binary security boundary.

      With installation off, inspection mode uses approved Nix programs of the isolated runtime. Selecting a suggestion does not grant access until you click Add program. Required bundles are listed after the first build; revoking their primary store roots can break OMBP and cannot take back loaded code. Saved inspection grants are kept when switching modes. Private folder changes require a new launch.

      A nested Wayland compositor separates OMBP from host screen/input protocols. No host display socket, X11, session bus, portals, Podman socket or host program execution. This is not host-desktop automation.

      This is a host-resource whitelist, not a ban on arbitrary code inside the container. GPU and display changes require a new launch. GPU selection is detected at UI startup; manual overrides are kept.

          Websites & internet

          i

          Every subpath is allowed. Subdomains are allowed by default over http or https (a leading www. is ignored); untick Subdomains for exactly the listed origin. Auto-approve: "google.com" lets through any host containing "google" and ending in ".com" (such as update.googleapis.com, but also look-alikes); an entry without a dot matches any host containing it. Settings edits that list. Listed websites may also reach private-network addresses, such as hosts behind a VPN connected on the Mac; everything else private, host loopback and direct connections are blocked. HTTPS is inspected using this launcher's local CA; clients must trust it. Upstream certificates are verified against the public roots plus, on macOS, the System keychain's CA certificates. WebSockets work to allowed sites; certificate-pinned clients fail closed.

          Optional host-side Authorization injection keeps the stored header outside the container and is sent only to the exact origin. Store it using secret-tool store --label='OMBP API' application ombp-start origin https://api.example.com, then enter the complete header value at its prompt (for example Bearer …). Trust that origin: its responses could echo the credential. Otherwise use the container's private keyring; the AI can read credentials there.

            Denied attempts

            i

            Gateway-observed website, folder and program attempts. Use + to grant folder/website access live. In installed mode, a program's + opens Choose tools for the next Start and keeps the denied row; inspection mode grants programs live.

            Allow all network traffic switches the website whitelist off (private networks and host loopback stay blocked). Latest 500 distinct denied resources, with counts. Direct network syscalls and missing programs outside the gateways cannot be identified here. Revocation cannot undo data already read or code already loaded. Hide language-server denials filters program names without deleting history or granting access. It cannot distinguish probes from other uses of shared commands such as tsc or deno. Folder and website denials remain visible.

            Choose container tools

            Saved selections apply on the next Start or restart, not to a running container. Saving does not install anything; packages are built in the isolated Linux runtime when OMBP starts.

            Always installed · required core

            The selected OMP/OMSP CLI and OMBP, including Bun, Node, Git, source-index Python and keyring tools; sandbox Python, Bash/sh, coreutils, D-Bus, private keyring, fonts, Podman client and the Zenity picker. AMD launches on Linux also include Mesa.

            Pinned local servers, toolchains, checkers and debugger adapters. Their runtime dependencies are included; project libraries, lockfiles and debug targets remain project-specific. Hover a choice to see its commands. Package selection is not a per-binary restriction. Host folder grants and the network gateway still apply. Leave every optional package unchecked for core only.
